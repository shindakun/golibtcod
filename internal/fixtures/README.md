# Golden fixtures

`fixtures.txt` and `fixtures_namegen.txt` are **ground truth generated by
the actual libtcod C code**, not by this port. They are the primary
fidelity evidence for golibtcod.

## How they were produced

The libtcod C sources were fetched from `github.com/libtcod/libtcod@main`
and compiled directly with gcc; the engine-independent modules (rng, fov,
path, bsp, noise, heightmap, bresenham, parser, namegen) have no SDL
dependency, so they build standalone:

    gcc -w -c -I<libtcod/src/libtcod> mersenne_c.c fov_c.c fov_*.c \
        path_c.c bsp_c.c noise_c.c heightmap_c.c bresenham_c.c \
        parser_c.c lex_c.c namegen_c.c color.c error.c logging.c \
        list_c.c tree_c.c
    gcc -I<...> gen.c *.o -lm -o gen && ./gen
    gcc -I<...> gen_namegen.c *.o -lm -o gen_namegen && ./gen_namegen

The generator sources are kept here as `gen.c.txt` and
`gen_namegen.c.txt` (the `.txt` suffix stops the Go toolchain from
treating them as cgo input). `mkname.cfg` is the syllable-set config used
by both the C generator and the Go test.

## What is covered

| fixture | contents |
|---|---|
| `rng_*` | 1,664 values: raw stream, floats, ranges, gaussian & inverse-gaussian distributions, dice (MT and CMWC, 4 seeds each) |
| `bres` | 53 cells across 7 lines (all octants, degenerate, negative coords) |
| `fov` | 7,264 cells: 8 algorithms x 6 scenarios (2 maps, radius/unlimited, lightWalls on/off, corner POV) |
| `astar` / `dijkstra` | full paths (map-based and cost-function, diagonal and orthogonal) plus the whole distance grid |
| `bsp` | complete pre-order node dumps (x,y,w,h,level,horizontal,position) for 3 seeds |
| `noise` | 420 values: perlin, simplex, fbm, turbulence in 1-4D, plus wavelet in 1-3D |
| `heightmap` | 1,388 values: a full hill/dig/fbm/erosion/normalize chain, interpolation samples, and a 33x33 midpoint-displacement map |
| `namegen` | 208 generated names across 3 rule forms and 2 seeds |

## Tolerance policy

Integers, grids, paths, tree geometry and generated strings must match
**exactly**: any difference fails the test. Floating-point fixtures allow
1e-5 relative error (with a 1e-6 absolute floor for near-zero values) to
absorb C compiler reassociation and x87/SSE differences; in practice most
values are bit-identical, and the tests log the exact split, currently:

- noise: 341/420 bit-exact
- heightmap: 1333/1388 bit-exact

To regenerate after changing the C baseline, rerun the commands above and
copy the resulting `.txt` files here.
